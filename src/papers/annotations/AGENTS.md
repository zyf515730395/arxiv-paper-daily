# 论文分类模块规则

- 本目录只负责配置驱动的论文主题、细节标签、`paper`/`survey` 分类与有证据的机构提取，不负责论文筛选决定或摘要正文生成。
- 模型只能通过共享 loopback transport 调用；原始输入、响应、缓存和报告只能写入已忽略的 `build/paper-summaries/`。
- 公开分类真源固定为 `content/papers/paper-annotations.json`，写入前必须完成严格 schema 校验并使用原子替换。
- 标签名称、顺序、维度和判定说明只来自 `config/site.yaml`；代码不得硬编码可选标签。每个主题必须配置至少三个非空技术维度，任务类型与应用领域不得作为细节标签；每篇论文只允许选择其当前归档主题维度集合并集中的标签。
- v2 公开分类继续将导航 `topics` 与扁平 `tags` 分开；标签维度由配置映射推导，不改变公开存储格式。v1 分类只迁移主题，不据此编造技术标签。
- `institutions` 仅记录原文署名区域明确提供的机构。无法核验时保留空列表，界面显示 `-`；不得根据作者姓名或摘要猜测。
- 本模块可从已获取的 HTML 署名元数据提取机构；PDF 无可靠署名结构时保持缺失。推理提示只读取标题、摘要和配置词表。
- 细节标签不得描述人物、肖像或角色等对象类型；只选技术相关维度。显式全量复核由上层 `papers.recheck` 编排并替换旧分类，主题删除不属于本模块。新的标签策略必须升级提示词版本，避免复用旧策略分类缓存。
- 单篇失败必须与其他论文隔离；历史 archive、候选 ledger 和摘要页面不得因分类失败被修改。
- 所有新增测试、fixture 和 mock 仅放在 `build/`，验证后删除且不得提交。
