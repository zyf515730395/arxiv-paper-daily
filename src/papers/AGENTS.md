# Paper pipeline rules

- Cloud collection treats exhausted HTTP 429 as a collection-wide pause: retain incomplete-topic cursors, save completed topics, emit a local JSON report, and return a nonzero CLI status. Scheduled catch-up runs skip when every topic has completed the current UTC day. Never report a deferred collection as successful or advance incomplete cursors.

- Conference attribution comes from `content/papers/conference-papers.json`, a versioned catalog of official accepted-paper lists from configured editions since 2024. `proceedings.py` owns collection and deterministic matching. Never infer acceptance from topic, author affiliation, submission, or fuzzy title similarity. Keep failed/pending editions explicit and preserve previously collected lists on fetch failure. Raw responses and coverage reports belong under ignored `build/conferences/`.
- The paper table displays Conference instead of Institutions; affiliation annotations remain preserved. Render conference names without years linked to the official paper/list. Weekend maintenance checks edition dates and list availability before refreshing and rebuilding.

- `content/papers/archive.json` is the canonical arXiv archive input; `content/papers/conference-library.json` adds title-screened conference papers. arXiv candidate decisions remain in `content/papers/arxiv-candidates.json`; paper topics, detail tags, institutions, and `paper`/`survey` types remain in `content/papers/paper-annotations.json`.
- The ordered label taxonomy and model-facing descriptions come only from `config/site.yaml`. New labels must not be hard-coded in Python or JavaScript.
- `src/papers/site.py` owns the paper archive view. `docs/index.html` and `docs/search-index.json` are generated outputs and must not be edited by hand.
- Ordinary papers are grouped into year and month by their publication date, then into three fixed day ranges: days 1-10, 11-20, and 21 through the end of the month.
- Surveys appear only in the yearly `Surveys` period; ordinary papers appear only in monthly periods. A multi-label paper may appear in each matching label view, while search remains deduplicated by arXiv ID.
- Preserve existing historical archive visibility and review decisions. New daily candidates collected since collection.review_required_since must be explicitly accepted before appearing in public lists, counts or search; pending candidates stay in the ledger.
- Topic navigation comes from `paper_labels`; detail tags come from `paper_tag_groups` in the same config. Topics and tags are independent. Topic aliases preserve historical archive and summary URLs; removed topics have no navigation entry.
- Institutions are evidence-backed author affiliations; missing or unreliable evidence renders as `-`. Annotation inference must not guess affiliations from author names.
- The current learning-taxonomy contract is defined by this file and config/site.yaml; superseded plans are available in Git history. Temporary test scripts live under ignored `build/` and are deleted after verification. Preserve review lists, source evidence, capacity reports and publication receipts needed for user review or recovery.
- Keep model calls loopback-only and private inputs, responses, caches, reports, and test artifacts below ignored `build/`. Follow the narrower rules in `annotations/` and `summaries/` when editing those modules.
- Explicit full-archive rechecks use `python -m papers recheck`: deduplicate and process numeric arXiv IDs newest first, override prior decisions only through fresh evidence, remove rejected topic memberships, and remove a paper only when all memberships are rejected. Unknown decisions and failed inference never authorize removal. Recheck state, per-paper receipts and recoverable public-write journals live under `build/paper-summaries/recheck/`; original sources, Markdown and older batch checkpoints are preserved. Reuse the runtime and public-write locks, yield to daily work between batches, and never push Git from the recheck command.
- Detail tags describe methods, representations, conditioning, controls and other technical dimensions. Task types and application domains are not detail tags; topic navigation remains separate. Each topic needs at least three nonempty technical dimensions. Rechecks replace existing annotations and fill missing summaries; tag count and per-dimension limits remain unchanged.
- Local paper inference uses the deployed Qwen3.8 model through one shared default in model_runtime.py. Measure context capacity on the actual GPU and concurrent workload; distinguish total context from completion allowance. Preserve old recheck receipts/checkpoints when explicitly starting a new model/taxonomy pass, and re-evaluate all configured topics so misclassified papers can move to the correct topic. Unknown judgments never authorize removal.
- Every loopback inference path shares the persistent busy-wall budget under `build/inference-budget/`: after 7200 seconds of cumulative inference activity, drain requests already in flight and complete a 600-second rest before admitting new requests. Concurrent requests do not multiply elapsed time. Paper counts never trigger rest, and rest state survives process restarts.
- Named full passes store private state under `build/paper-summaries/recheck/runs/<run-name>/`; the shared local-only publication marker stays in `build/paper-summaries/recheck/`. `conference_recheck.py` reviews the conference overlay using official titles and identity/checksum-verified cached official abstracts. Empty topics are permitted only with explicit all-false `topic_review` decisions; these retained tombstones remain hidden and intake cannot undo them. Its inputs/responses and recoverable journal use the same named private run. No generated summary is treated as source evidence.
- Topics-only rechecks obtain missing or oversized abstracts from identity-verified official abstract pages before attempting full-text acquisition. An unavailable PDF must not prevent classification when verified abstract evidence is available; summary generation still requires its usual source material.
- Explicit user review decisions take precedence over model relevance uncertainty. Preserve the instruction and previous decisions in private receipts; record user-authorized acceptance/deletion as such, without presenting it as model evidence. The 2026-09-11 follow-up applies to the delivered review table: confirm its 30 pending deletions, continue its uncertain public papers, and exclude primarily medical, clinical or biomedical applications using source-backed local inference. Ambiguous medical-domain judgments remain pending. Original sources and summaries are preserved when removing public archive membership.
- Failed rechecks use schema-constrained local generation with per-paper configured tag enums, followed by the same strict semantic validators; never repair arbitrary malformed JSON or widen tag allowlists. Recovery revisions invalidate only selected papers' private inference receipts, not the original queue or successful public results. Restarting a recovery pass preserves its checkpoint and includes both unfinished IDs and remaining failed/uncertain IDs.
- Recheck ledger records include canonical per-topic `recheck_decisions`; batch consumers must honor accepted, rejected and uncertain values before the legacy single selected_topic field. During review, `build/paper-summaries/recheck/local-only.json` disables runtime Git synchronization/publication while allowing local daily work. Keep that marker until remote publication is explicitly authorized; local recheck commits must not be automatically pushed by another runtime job.
- When publishing a paper-pipeline change, commit the relevant source/config/data together with every affected generated page or index; never stage local test or cache artifacts.
- `python -m papers` is the public command entry; `python -m papers.runtime` owns WSL scheduling, model lifecycle, batch priority and restricted Git publication. Root-level legacy scripts are retired.
- Collection writes only the candidate ledger. Daily curation processes pending IDs using title/abstract/config only; concurrent public edits abort application. Public pair updates use a recoverable private journal.
- Daily summary and annotation selection prioritizes unattempted work, then rotates retries using private attempt counters so repeated failures cannot block the queue.
- Weekend batches preserve the existing v1 checkpoint and caches, yield to daily requests between batches, and publish validated missing annotations only after their summaries are publicly ready.
- Historical backfill holds the runtime lock for one checkpoint batch of 100 papers, publishes that batch, then releases the lock so waiting daily work can proceed. A failed runtime push may retry only the commit recorded in `build/paper-summaries/pending-runtime-push.json`; it must not publish unrelated local commits.
- `config/conferences.yaml` defines enabled conferences and actual editions, including historical and future records; each edition retains an official source and verification date. Optional `website` links to the edition homepage and `proceedings_url` to its accepted papers or proceedings. Missing proceedings remain visibly pending. The Conference Timeline displays the current calendar year and preceding two years in chronological order, initially positioned at the current year. Unannounced dates remain visibly pending; biennial meetings must not invent off-year editions.
- 改进复核必须把公开归档中缺少技术标签的文章加入恢复队列；已接受论文仍返回空标签时，要求模型依据现有白名单和证据重试一次，仍为空则记录 annotation_tags_missing，不能把漏标算作成功，也不能猜测标签。
- 恢复复核可补充已通过相同身份验证的缓存原文引言，最多18000字符并明确标记截断；不得用任意正文冒充引言。全部主题被拒绝时无须进行保留主题标签过滤。轮次进度比较必须同时比较 round 和 offset。
- 两次综合复核仍漏标时，可独立调用本地模型提取标签；每个标签必须附所给标题、摘要或引言中连续的原文证据并通过匹配验证，仍遵守保留主题白名单与数量限制。私有证据回执必须保留，不允许把模型生成的判断理由当原文证据。

## Conference library intake
- Conference technical annotations are stored in each conference-library record's optional `annotation` field, using the same configured taxonomy and per-topic limits as arXiv annotations. Render these validated tags in public rows; do not insert conference IDs into the arXiv annotation catalog. Targeted evidence recovery stores source receipts and checkpoints under ignored build/paper-summaries and requires identity-verified abstracts before local inference.
- `conference_library.py` owns the public `content/papers/conference-library.json` overlay and its website rows. `conference_intake.py` owns newest-first title screening, deduplication, and resumable local summary batches; `conference_sources.py` acquires official paper metadata and source documents. Private receipts and original sources stay in ignored `build/conferences/intake/`.
- Conference labels show the configured name without a year; edition/year evidence remains stored. Non-arXiv display IDs are `YYMM.DDXXX`, with `XX` for unknown month/day. They are never real arXiv IDs; internal IDs derive from DOI or official URL. Do not infer paper publication dates from meeting dates; unknown dates remain unknown in the UI.
- Positive title-only screening against `config/site.yaml` may publish a conference paper before its summary. Preserve explicit prior rejections by arXiv ID and normalized title. Ambiguous titles remain pending. Treat medical/clinical/biomedical application-only titles as excluded under the existing user review rule.
- Deduplicate the conference overlay against the arXiv archive and candidate ledger; enrich existing records rather than restoring reviewed-away papers. Retain provenance, exact screening basis, and retry receipts. Intake and summary batches run newest first and share the public-write/model runtime locks; daily work takes priority between batches. Summary failure never removes an accepted entry.
- Source adapters permit only configured official proceedings hosts and explicitly supported publisher/arXiv hosts, verify title identity and usable abstract/introduction, and retain originals. Do not expand the existing arXiv-only acquisition contract or fabricate body content from titles.
- `python -m papers.conference_intake review` runs the title-only local model on configured phrase candidates, newest editions first, with per-batch receipts. `screen --apply` imports only positively reviewed titles. `summarize --limit 20` runs a bounded operational slice; `summarize --all` makes one weekend pass over every eligible summary or missing-annotation item. Each item is attempted at most once per pass, with unattempted work ahead of rotated failures. Missing/failed/ambiguous titles and sources stay resumable and never masquerade as completed work.
- Weekend proceedings refresh uses conditional HTTP revalidation for successful cached sources. Private cache receipts retain validators and content hashes; public editions and paper identities retain deterministic source versions. One selected source edition owns each deduplicated record's top-level acquisition identity; secondary or older editions may update only their provenance. When the selected paper identity or its version changes, intake synchronizes that record's verified official identity, marks its generated summary and technical annotation for refresh, and preserves the last successful public results until each replacement succeeds. Human review decisions and stronger publication-date evidence remain unchanged. A first-time version baseline skips refresh only when title, URL and any supplied DOI/arXiv identity are unchanged; changed versions use separate private cache directories so older originals remain recoverable.
- Conference summary intake classifies technical tags from the same identity-validated official paper evidence. It uses the configured topic tag allowlists and strict annotation validators, retries an accepted paper once when tags are empty, and reports remaining empty tags as `annotation_tags_missing`. Summary and annotation outcomes are checkpointed independently; either failed stage keeps the item retryable and contributes to the batch failure count.

## Conference publication metadata
- User-authorized webpage-date fallback belongs in `conference_web_dates.py`: verify the page contains the paper title, then use page publication/modification metadata, paper schedule, explicit page-generation date or HTTP Last-Modified. Record the exact evidence and distinguish it from paper publication in the UI. Never use HTTP Date, retrieval time or invent missing calendar components. Scholarly dates take precedence over fallback dates. Run `python -m papers.conference_web_dates --apply` after arXiv/fuzzy lookup; private receipts remain in `build/conferences/dates/`.
- Fuzzy discovery separates candidate retrieval from identity verification. `conference_fuzzy.py` handles normalized title variants and evidence-backed ranking; `conference_discovery.py` discovers official/IEEE/GitHub metadata and links. Matching may tolerate abbreviations, formula formatting and subtitles, but never merge on a similarity score alone. Preserve conflicting numbers and negations. Require corroborating authors, DOI or verified official links and reject competing plausible candidates. GitHub creation/commit timestamps are not paper dates. Private candidate receipts remain under `build/conferences/dates/`.
- `python -m papers.conference_dates --fuzzy --apply` reruns remaining identities through variant arXiv queries and web discovery; `--arxiv-only` and `--web-only` separate phases. Cached web-discovery receipts are title-bound. Fuzzy runs publish only after final review against all retrieved candidates; interrupted runs retain private caches and recompute matches before publishing. GitHub README citations remain candidates and undergo the same title/author checks; actual author evidence URLs are retained. GitHub limits halt that source while independent official/IEEE lookups continue.
- Conference-library records remain browsable when verified preprint dates precede the normal archive window; this exception must not expose unrelated older arXiv archive entries.
- `conference_dates.py` resolves missing conference paper dates newest first: arXiv title search and verified first-submission metadata first; then official paper pages and DOI/publisher metadata. Never treat a revision timestamp, crawl time, event date or inferred ID prefix as paper-publication evidence; the explicitly labeled webpage fallback above may use page modification or paper event dates.
- Metadata lookup is independent of full-text acquisition and summary success. Preserve a public source URL and date basis for each resolved value; requests, ambiguous candidates and retry reports stay under `build/conferences/dates/`. Keep existing library IDs stable, expose verified arXiv IDs and link to their abstract page, and preserve all existing user review decisions.
- Exact normalized titles can identify a unique result. Changed/ambiguous titles require explicit official arXiv links or corroborating author/DOI evidence; fuzzy title similarity alone never authorizes automatic replacement. Failed lookup preserves existing values. Monthly intake resolves dates before starting body summaries.
- Run `python -m papers.conference_dates --apply` for verified updates, `--resume` to continue an applied web pass, and `--refresh` for weekend rechecks. arXiv requests observe spacing and HTTP 429 backoff; other official metadata lookups may continue. A dry run must never mark unapplied results as applied. Body summaries do not write publication dates.

- Historical conference summary runs may use `summarize --skip-failed` to exclude existing failed receipts. Per-paper acquisition or inference exceptions are recorded by exception type and do not terminate the queue; interrupts, memory exhaustion, and failures writing checkpoints remain fatal. Preserve skipped records and their source evidence.
